# V4 与 0.3.0：GUI 和 AI 共用一台下载器

配套 V4 固件与 0.3.0 上位机把 RTT、SuperWatch 和命令收发放到同一条 CDC
多路复用链路中。电脑上的共享后台持有下载器，桌面、网页、CLI 和 MCP 使用
这个后台。无需增加 WinUSB，也不需要 AI 为读一个变量抢占 GUI 的串口。

本页按实际任务说明配套开发版本的使用方式：一边看曲线，一边让 AI 读取同一台
下载器的数据；需要烧录或调试时，先确认采集状态，完成后再开始新一轮观察。

## 开始前：确认配套版本

!!! warning "适用于配套 V4 固件 + 0.3.0 上位机与 Skill"
    这里的共享后台、八路 RTT 和采样改进需要配套的 V4 固件与 0.3.0 上位机。
    要让 AI 共用设备，还需要同版完整 Skill。仅更新其中一项，或使用 V2/V3、
    旧固件，不能据此判断这些功能可用。只用 GUI 时无需安装 Skill。

1. 核对下载器型号，按[固件升级](../flashing/firmware-upgrade.md)选择对应 V4 固件。
2. 按[安装与开始](../getting-started/gui-install.md)安装配套上位机；让 AI 操作时，
   同时更新[完整 Skill](../../embedded-ai/getting-started/skill.md)。
3. 打开应用，在“配置”中连接具体设备，加载与板上程序同一次构建的 AXF/ELF。
   先确认设备在线、符号加载完成，再开始下面的任务。

截至 2026-10-06，V4 固件 [PR1](https://github.com/Aladdin-Wang/MicroLink_Plus/pull/1)
已合并；配套上位机仍在 [PR30](https://github.com/MicroKeen/Mklink-AI-Probe/pull/30)
草稿中，0.3.0 已完成本地安装态验收，尚不能当作公开正式版本。
公开安装包以[官方发布页](https://github.com/MicroKeen/Mklink-AI-Probe/releases)为准，
不应把当前公开安装包默认视为本页的配套开发版本。

升级共享后台时，先结束正在进行的任务，从旧版后台管理页正常退出，再启动新版。
不要混用不匹配的后台与客户端；完整安装步骤仍以对应版本说明为准。

<a id="shared-device"></a>

## 两台下载器，各自连接

在配置页选择具体下载器再连接。设备身份依据 USB 序列号，COM 编号变化不会
把会话切到另一台。配置页底部“后台管理”可以设置本机别名，例如“电机板”
和“控制板”；别名保存在电脑上，不改变固件和 USB 序列号。

缺少或重复 USB 序列号时，只能使用临时位置身份，不能保存持久别名；
更换 USB 接口后应重新核对设备，不依赖之前的端口顺序。

同一下载器的多个客户端共享工程、符号和采集设置。不同下载器各有后台，建议
使用不同工程目录。告诉 AI 要操作哪个设备，避免让它选择枚举列表的第一台。

1. 在第一个窗口选中设备并加载工程，开始需要的 RTT 或 SuperWatch 采集。
2. 第二个桌面或网页窗口选择同一台设备；让 AI 使用对应设备身份接入已有后台。
3. 只需分析数据时，让 AI 复用当前采集。更换工程、符号或采样设置前，先与其他
   使用者确认，因为这些设置会影响连接这台下载器的所有客户端。

> 连接“控制板”，复用已经运行的采集，读取最近的变量值，不要停止其他窗口。

最后一个客户端离开且没有进行中的任务时，后台约 5 秒后开始正常退出，随后
完成清理并释放串口。烧录期间和仍有其他客户端连接时不会因为关闭一个窗口而退出。

需要改用独占串口的第三方工具时，先结束共享任务、退出相关客户端，并确认后台
已释放命令口。关闭一个窗口不代表设备连接已经释放。

<a id="rtt-channels"></a>

## 八个 RTT 通道，同样的功能

RTT View 可选择 0～7 通道，每路分别显示日志、终端、HEX 或曲线，并向该路
实际存在的输入缓冲发送数据。通道之间没有“主日志通道”的区别，收起面板
不会删除其他通道的历史；缓存有上限，长时间保存应导出记录。

八通道能力需要目标程序配置相应 RTT 缓冲区。选择一个未初始化的通道会报错，
不会由下载器自动创建。例如目标仅提供通道 0，就不能直接选 0～7。
原有 [RTT 使用原理](../articles/mcu-debugging-companion.md)仍适用。

1. 打开 **仪表盘 → RTT View**，用当前符号定位 RTT，或在已知目标 RAM 内搜索。
2. 选择目标实际启用的通道后开始采集；例如目标已初始化 0、1、2 三路，才填写
   `0,1,2`。每个面板可分别选择日志、终端、HEX 或曲线。
3. 发送前确认该路有输入缓冲区和目标端处理代码，选择需要的换行方式，再发送
   一条已知安全的查询或回显指令。按该路收到的响应核对结果。
4. 需要留档时及时导出。收起面板、暂停显示和停止采集是不同操作，不能用收起
   面板来判断设备是否仍在采集。

> 在“控制板”上查看 RTT 通道 0 和 1 的日志。确认通道 1 已接入命令行后，发送
> help 并保留回应，不要改动其他通道的采集设置。

第三方串口助手所用的传统 RTT 串口映射仍保留，但必须先释放共享后台持有的
命令口。GUI、CLI 和 MCP 使用新多路复用方式；VOFA+ 作为第三方兼容协议保留，
GUI 中不再提供独立 VOFA+ 页面。

<a id="sampling"></a>

## SuperWatch：采样与显示分开看

RTT 按 1 ms 轮询。SuperWatch 使用独立采样周期：当前配套 V4 固件设置
1 μs（0.000001 秒）表示全速，不承诺达到 1 MHz；更长周期按目标读取能力调度。目标读取本身
耗时超过周期时不能保证设定频率；多变量也不是同时发生的原子快照。

1. 打开 **仪表盘 → SuperWatch**，选择变量。日常观察可先从 1 ms 间隔开始，
   用实际数据检查目标变化，再决定是否需要全速。
2. 改变调试速率或采集设置前先停止共享采集，应用设置后重新开始。其他客户端
   也在使用同一设置，不能把单个窗口的操作当成独立采集。
3. 观察一段完整过程，暂停查看局部；需要结束读取时明确点击“停止”，并保存
   CSV 或图片。用原始时间戳检查间隔，不只看界面上的平均采样率。

测量峰值时单独运行 SuperWatch，再单独验证 RTT 共存。单字节、半字、4 字节
和非 4 字节对齐变量均按实际地址和类型读取，不要求用户补齐地址。

新版时间轴采用 1/2/5 档栅格并标出每格时长，缩放时自动使用 μs、ms 或 s。
暂停或停止后缩放，再开始时保留时间窗口宽度；只有有限历史时，能显示的范围
仍受已保留数据限制。采样率、传输吞吐和 GUI 刷新率是不同指标。

传输丢弃计数为零不代表没有漏采：目标在两次采样之间发生又恢复的变化仍可能
看不到。分析连续性应查看原始采样时间戳的相邻间隔，而不只看平均 Hz。
新版缩短了集中批间停顿，但不承诺零抖动或零漏采。

<a id="dap-restart"></a>

## 下载和仿真优先

CMSIS-DAP/OpenOCD 下载、暂停、单步和运行优先于 RTT/SuperWatch；下载器
屏幕刷新排在采集和调试工作之后。外部 DAP 工具改变目标后，旧采集会失效，
并向客户端报告原因。调试结束、确认当前固件及符号后，显式重新开始采集。

1. 由本地 GUI、CLI 或 MCP 发起烧录、复位、调试控制或调试速率修改前，先明确
   停止共享采集，按对应入口的提示操作。外部 DAP 抢占能力不替代这一步。
2. 完成下载或单步调试后，确认目标已处于需要的运行状态。重新核对板上固件、
   当前工程和符号文件；重新编译后，旧变量地址和 RTT 控制块可能已经变化。
3. 重新选择当前需要的通道和变量，显式点击“开始”。先检查日志、运行计数或
   变量值是否合理，再继续分析。

不会自动向新固件重放旧 RTT 输入、变量写入或过期地址。GUI 自身发起的烧录
仍遵守页面的停止采集提示。正在执行的任务不能用关闭窗口当作可靠取消。

<a id="hpm-flashing"></a>

## HPM 的 HEX 文件

HPM5301 配套路径支持 BIN 和 Intel HEX 的在线、脱机烧录。BIN 需要明确基址，
HEX 使用文件内的地址；不要把 HEX 文本当成 BIN 复制。仍使用 HPM ROM API，
无需也不应为 HPM 选择 Cortex-M FLM 算法。执行前核对精确芯片、板卡、Flash
配置和镜像范围，不能用未知型号或错误基址绕过检查。

1. 在线烧录时选择准确的 HPM 芯片和板卡，加载当前构建的 BIN 或 Intel HEX。
   BIN 填写工程给定的下载基址；HEX 核对文件内的地址段及预览范围。
2. 核对 Flash 配置及需要保留的区域，停止采集后执行下载与校验。完成后检查
   目标运行状态，再按当前固件更新符号并重新开始观察。
3. 需要脱机使用时，将同一份已核对的镜像及板卡、Flash 配置保存为脱机任务；
   在实际目标板上完成一次触发、校验和启动检查，再用于重复烧录。

具体操作见[在线烧录](../flashing/online-flash.md)、
[脱机下载](../flashing/offline-flash.md)和[HPM 实战](../hpm/overview.md)。

## 远程查看：先在设备所在电脑配置好工程

配套版本的远程 GUI 复用已有的 RTT View、Memory、SuperWatch、HardFault、符号
和 RTOS Trace 页面。它连接的是设备所在电脑上的服务，工程与设备配置仍由该电脑管理。

1. 先在设备所在电脑连接下载器、加载当前符号，并确认本地观察正常；
   在“远程服务”中选择设备并启动服务。
2. 操作电脑使用服务地址和访问令牌接入，在新窗口打开远程仪表盘。确认设备
   身份与工程后再操作；原本地窗口仍连接原设备。访问凭据不要放入公开截图、
   日志或共享链接。
3. 连接中断后，已显示的数据不能作为实时状态。明确重新连接，核对当前状态
   再继续；不要自动切换到本地设备，也不要重放上次未确认结果的 RTT 输入、
   变量写入或其他命令。

远程 GUI 目前不提供烧录、串口 / Modbus、VOFA+、文件上传、主机录制文件访问或
后台管理。需要这些操作时，回到设备所在电脑使用相应本地入口。

本轮只完成**同一物理电脑上的 LAN 路径验证**，尚未完成跨物理主机验证。
不能把同机结果当作任意网络、异地部署或长期在线的保证。

## 遇到这些提示，先这样处理

| 现象 | 下一步 |
| --- | --- |
| 第二个窗口连到错误设备 | 回到配置页核对 USB 序列号和本机别名，不按 COM 顺序猜设备 |
| RTT 通道未启用或发送无回应 | 核对目标是否初始化该路输出、输入缓冲区和对应处理代码 |
| 修改调试速率只显示 Conflict | 先停止共享采集，再修改；仍有其他客户端时一并核对它们的状态 |
| 下载或调试后曲线不再更新 | 核对当前固件与符号，重新选择变量并显式开始采集 |
| 另一窗口仍显示历史停止提示 | 结合当前运行状态判断，必要时刷新状态；不要仅凭旧提示重复写入或下载 |
| 传统串口工具提示端口占用 | 结束共享任务并退出相关客户端，等待后台释放命令口 |

## 这些说明验证到了哪里

STM32 与 HPM5301 是这次配套验证的实体目标，其他型号不能由此推断全部通过。
长期运行、跨物理主机网络和未接入的外部协议设备需要各自的验收环境。
STM32 完成了八路 RTT 双向验证，HPM 按目标程序实际启用的通道验证；HPM5301
完成 BIN / Intel HEX 在线及脱机四条路径核对，不等于所有 HPM 型号均完成同样测试。
