# GUI 与 AI 共享一台下载器

配套上位机通过共享后台持有下载器，GUI、CLI 和 MCP 使用同一连接。
RTT、SystemView、SuperWatch 与内存访问复用 CDC MUX，不需要再开一个串口。

<a id="version-check"></a>

## 开始前检查

1. 安装匹配的上位机和下载器固件，让 AI 操作时同步更新完整 Skill。
2. 在配置页选择具体下载器，加载与目标固件同次构建的 AXF/ELF。
3. 核对 `MUX_TARGET=1` 与 HELLO 能力。V3、V4 按各自能力使用，不能仅凭型号判断。

截至 2026-11-07，正式上位机为 v0.4.2；0.4.3 main 的新采样契约与 Bulk
需要配套开发固件。版本、能力和协议见[内部 API](python-api.md)及[MUX](mux-protocol.md)。
升级前结束任务、正常退出旧后台，避免新旧客户端混用。

<a id="shared-device"></a>

## 选择设备与共享设置

多个窗口和 AI 选择同一 USB 序列号对应的下载器，便可复用已有采集。
同一设备的工程、符号和采集设置共享，修改前留意其他使用者；不同下载器建议使用独立工程目录。
可用本机别名区分板卡，COM 编号变化不代表换了设备。

缺失或重复序列号时应重新核对物理设备，不依赖端口枚举顺序。关闭一个窗口不会取消
其他客户端或正在执行的任务。第三方独占串口工具须等共享任务结束、后台释放命令口后再使用。

> 连接“控制板”，复用当前采集读取变量和 RTT 日志，不要停止其他窗口或修改参数。

<a id="rtt-channels"></a>

## 多通道 RTT / SystemView

RTT View 按目标实际初始化的缓冲区选择 0～7 通道。每路可查看日志、HEX 或曲线，
下行发送还需要对应 DownBuffer 和目标端处理代码；未启用的通道不会自动创建。
RTT 和 SystemView 共用同一控制块，各消费者独立取数，不为每个页面重开串口。

暂停显示、收起面板不等于停止采集，长期记录应及时导出。
直接使用 `RTTView` / `vofa.send` 传统串口流的第三方工具是独占兼容路径，
不能与共享后台抢同一命令口；现代 GUI / MCP 的 VOFA 使用共享采集入口。

<a id="sampling"></a>

## SuperWatch：周期与全速分开

先用适当周期观察目标变化，再按需要选择全速。当前开发版显式全速发送周期 0；
普通周期 0 仍兼容为 2000 μs，不再把 1 μs 写成通用“全速协议”。
实际时基由 START ACK 返回，读目标耗时超过周期时不能保证设定频率。

采样率、传输吞吐和 GUI 刷新率是不同指标；零传输丢弃不代表没有漏采。
结合原始时间戳、间隔和丢弃计数判断连续性，多变量和 Bulk 均不是原子快照。
修改布局或速率前先停止相关采集，确认新固件与符号一致后再开始。

<a id="dap-restart"></a>

## 下载或调试后恢复

烧录、复位和调试控制通过共享后台的对应入口执行，不另开原始串口抢占。
外部 CMSIS-DAP/OpenOCD 操作可能使原采集失效；完成后重新确认目标运行状态、
镜像和符号，按当前地址显式开始采集。不要向新固件重放旧 RTT 输入或变量写入。

超时或回执丢失时先查任务与设备状态，不自动重复烧录、复位、写入，也不改道旧协议重试。

<a id="hpm-flashing"></a>

## HPM BIN / HEX

HPM 使用设备端 ROM API，不加载 Cortex-M FLM。BIN 提供工程给定的基址，
HEX 使用文件内地址；核对精确芯片、板卡和 NOR 配置后再执行。
脱机任务需在实际板卡完成一次烧录、校验与启动检查，再用于重复生产。

详见[在线烧录](../flashing/online-flash.md)、[脱机下载](../flashing/offline-flash.md)
及[HPM 实战](../hpm/overview.md)。

<a id="remote-view"></a>

## 远程查看

先在设备所在电脑连接下载器、配置工程和符号，再启动远程服务。
另一电脑按服务地址和访问凭据连接，核对设备身份后使用已开放的远程仪表盘。
远程与本地功能范围不同，不能把本地烧录、主机文件或后台管理能力直接推断为远程可用。

断线后的已有画面不是实时状态。重新连接后核对状态，不自动切换本地设备或重放命令；
访问凭据不要放入公开截图和日志。历史同机 LAN 结果不等于跨物理主机验收。
