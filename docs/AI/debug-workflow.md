# AI 辅助调试

## RTT 与变量异常

> 请加载本次构建的 ELF，采集 10 秒 RTT 原始日志，同时连续观察 `<变量名>`。用时间戳对齐两类证据，指出异常首次出现的时间。在确认前不要写变量或复位。

AI 应保留原始数据，避免只返回摘要。高速变量优先用 SuperWatch 或内存批量采样，不要用多轮文本命令拼凑时间线。

对于 PID 或 FOC，先选择给定、反馈、误差、输出和保护标志，固定采样周期后运行多个阶跃周期。AI 可以计算上升时间、超调、稳态误差和饱和比例，但写入 `Kp/Ki/Kd` 或 FOC 电流环参数前必须人工确认上下限、步长、急停条件和回滚值。

## 外设和 DMA

> 请读取 DMA、ADC 和 NVIC 的相关状态及计数寄存器，判断 DMA 是否还在传输。先列出寄存器地址来源和判定条件，再采集证据。

寄存器值需要结合芯片参考手册解释；只看到某个位为 1，不足以证明根因。

## SystemView

SystemView 必须先通过有效性检查：任务数大于 0、时间基准正常、无 overflow、无持续丢包。否则只记录采集失败原因，不给出 CPU 占用结论。

HPM5301 实测的 8 秒高事件率窗口出现 1934 个 session drop，因此只能确认任务/ISR 结构，精确占用需要缩短窗口或增大缓冲后重采。不能为了让报告好看而省略这项限制。

## 闭环标准

每个修复都应完成“复现 -> 证据 -> 最小修改 -> 重烧 -> 同条件复验”。无法复现时，应明确剩余不确定性，不能把合理解释写成已验证结论。
