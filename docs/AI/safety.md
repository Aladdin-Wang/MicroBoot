# 安全边界与排障

## 操作分级

| 操作 | AI 默认策略 |
|---|---|
| 读取工程、AXF/ELF、MAP | 可直接执行并报告来源 |
| 读取 RAM、寄存器、RTT | 说明目标和范围后执行 |
| 持续采样 | 报告时长、请求频率、实际频率和保存位置 |
| 修改代码、编译 | 保持改动最小，保留构建结果 |
| 烧录、擦除、复位 | 先核对器件、镜像、地址和影响范围 |
| 写 RAM、写寄存器 | 说明地址、类型、原值、新值、回读和回滚值 |
| 故障注入、控制环调参 | 必须有保护条件、停止条件和恢复步骤 |

## 无界面调试常见问题

### AI 找不到 Skill

确认安装的是包含 `SKILL.md`、`references` 和 `scripts` 的完整目录，并重启 AI 客户端。旧会话不会自动重新载入更新后的 Skill。

### 找不到 `mklink` 模块

在 MKLink AI Probe 源码目录安装完整依赖：

```powershell
python -m pip install -e ".[gui,mcp]"
```

完整安装可以保证 MCP、CLI、API 和 GUI 使用相同的依赖版本。

### 找不到 MKLink 或提示资源占用

检查 USB 数据线、目标供电和设备管理器。正常停止 Keil、串口工具、RTT、SystemView 或旧后台作业，再重试。不要从两个入口同时操作同一探针或同一串口。

### 变量值明显错误

确认 AXF/ELF 与芯片固件来自同一次构建；核对芯片、优化级别、变量类型、地址和 SRAM 范围。地址随链接变化，旧文档或旧 MAP 中的地址不能直接复用。

### RTT 没有启动行

接入运行中的环形缓冲区时，一次性启动文本可能已经被覆盖。可结合 build_id、心跳或受控复位验证，不能补写未采集到的日志。

### 连续采样达不到请求频率

报告实际样本数、持续时间和实际频率。减少变量数量、改用多地址批量读取或降低请求频率；不能按配置值宣称采样成功。

### HardFault 自动解码不合理

先核对异常来自 MSP 还是 PSP，再检查 RTOS 异常入口额外压栈。PC/LR 必须与 CFSR/HFSR、异常类型和触发路径互相印证。现场采集完成前不要复位。

### SystemView 数字不可信

任务数为 0、时间基准错误、目标 overflow 或传输丢包时，不输出精确 CPU 占用。还要识别 idle 任务，避免把高空闲率误判为任务饥饿。

## 最终报告要求

AI 应列出固件和产物摘要、执行过的写操作、关键原始数据、已证实结论、工具限制、未验证风险，以及目标最终是否已恢复到安全运行状态。
