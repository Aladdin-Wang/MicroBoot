# 编译、下载，再确认程序真的在跑

**下载成功以后，让 AI 顺手检查系统节拍和任务计数。** 不必为了确认程序在运行，专门打开一个日志窗口。

> 把程序编译并下载，看看系统节拍和任务计数有没有在走。

![Codex 编译下载并检查系统节拍与任务计数](../../images/mklink/cases/stm32f103-rt-thread/codex-build-flash-runtime-check.png)

## 你需要提供什么

完整工程的位置、连接的板型，以及要使用的构建目标。有 BootLoader 或参数区时，说明哪些区域必须保留。AI 会使用工程已有的工具链，核对当前生成的固件与符号文件。

## 结果看这三件事

| 要确认什么 | 看什么结果 |
| --- | --- |
| 程序能否构建 | 编译完成，没有阻止生成固件的错误 |
| 新固件是否写入 | 下载和校验通过 |
| 程序是否继续执行 | 系统节拍、任务计数或业务心跳在一段时间内持续变化 |

截图中，AI 连续观察了约 5 秒：系统节拍递增，主任务计数从 120 到 170，四项任务计数均有变化。它说明这些任务正在执行；业务功能是否符合预期，还可以继续检查输出或通信响应。

> 再看看每秒处理多少次数据，和代码设置的周期是否一致。

裸机程序没有任务计数时，可以观察主循环计数，或让 AI 增加一个简单的运行标记。

## 想自己点下载

打开 **在线烧录**，选择器件和固件，核对下载地址后开始。BIN 的基址以工程为准，HEX 使用文件内地址。完成后检查校验结果，再让 AI 查看运行状态。

![Web 在线烧录](../../images/mklink/cases/hpm5301/online-flash-succeeded.png)

*HPM5301 在线烧录界面。HPM 使用 ROM API，需要准确板型和镜像地址，无需 FLM。*

重新编译后同步更新 AXF/ELF，避免用旧符号读取新固件。操作细节见[在线烧录](../../mklink/flashing/online-flash.md)。

程序确认好后，可以继续[观察曲线](pid-workflow.md)，或[准备脱机任务](offline-workflow.md)。
