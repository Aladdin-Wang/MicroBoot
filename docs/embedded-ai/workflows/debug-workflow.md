# 遇到问题，先看哪一项？

不用一次打开所有功能。从现象出发，选能回答这个问题的数据。

| 看到的现象 | 直接这样问 AI | 到哪里看 |
| --- | --- | --- |
| 下载完成，板子没动静 | 检查系统节拍和主任务计数有没有在走 | 对话中的运行检查结果 |
| 不知道程序支持什么指令 | 发个 help，看看能查哪些状态 | RTT View |
| 参数偶尔跳变 | 连续看这个变量，把异常前后的数据留下来 | SuperWatch |
| ADC / DMA 数据不再更新 | 看看缓冲区和传输计数还变不变 | Memory、芯片外设 |
| 调参后响应不如以前 | 把目标、反馈和输出放一起，比较两次响应 | SuperWatch |
| 程序进入异常 | 先保存现场，找到对应的代码 | HardFault / Trap 分析 |
| 任务响应忽快忽慢 | 看看任务什么时候运行，是谁占着 CPU | RTOS Trace |

## 一次只解决一个问题

例如反馈有过冲，先看目标、反馈和输出，保存一段完整响应。让 AI 根据数据提出修改，再用相同的目标变化和负载复测。

> 用相同条件再采一次，告诉我这次改善在哪里。

这时你比较的是改动前后的结果。没有覆盖完整响应，或数据中间丢失，就补采关注的那一段。

## 顺着结果往下查

曲线异常但变量类型正确，可以继续查相关任务；任务正常却没有通信回应，可以看 RTT 命令回显和外设状态。每次增加一种观察手段，都用来回答一个具体疑问。
