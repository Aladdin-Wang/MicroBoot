# 连接与使用排障

遇到问题，把页面提示和正在做的事告诉 AI，通常不需要自己补装依赖或尝试底层命令。

> MKLink 连接不上，帮我检查安装、设备占用和接线配置。

## 最常见的几种情况

| 现象 | 先怎么处理 |
| --- | --- |
| AI 不知道 MKLink 是什么 | 确认已安装完整 Skill，开启新会话；让 AI 检查客户端工具是否启用 |
| 网页只停在启动页 | 让 AI 检查本地服务；使用启动入口给出的地址，不沿用旧端口 |
| 找不到下载器 | 检查 USB 数据线、下载器连接和目标供电 |
| 提示设备被占用 | 结束原来的烧录或采集；图表“暂停”不等于停止占用 |
| 变量找不到或值不对 | 重新选择与板上固件匹配的 AXF/ELF，核对类型和是否被优化掉 |
| 发 RTT 命令没有回应 | 确认程序接了命令行输入，检查命令名称和换行方式 |
| 曲线实际速度低于设置值 | 看实际采集速度，减少通道或调整采集间隔；设置值不是保证值 |

## 重新编译后，别让旧符号跟着新固件

配置页显示“文件快照”时，重新选择新的符号文件；使用“自动跟踪”时，确认重载完成。重载会停止相关采集，确认新固件已下载后再启动。

## 程序死机，先保留现场

> 程序卡住了，先保存异常现场和任务状态，再看看问题在哪。

复位后，异常栈和寄存器可能已经变化。HardFault 定位需要匹配的符号文件；HPM 则检查 RISC-V Trap，不能套用 Cortex-M 的寄存器解释。

## 需要改写时，说明想改哪里

下载固件、修改参数和调整供电会改变板子状态。告诉 AI 需要保留的 BootLoader、参数区以及允许修改的范围。真实电机调参要先确定负载、保护和停止条件。

读取结果不够清楚时，可以直接追问：

> 哪些是你从板子读到的？哪些还需要验证？

有跳动的系统节拍，只能说明节拍在运行；应用是否正常，还要看任务计数和你关心的业务结果。
