# 固件升级

本页说明如何升级 MKLink 下载器自身固件。它与“把应用固件烧录到目标 MCU”是两件事：前者更新下载器，后者使用[在线烧录](online-flash.md)或[脱机下载](offline_download.md)。

## 升级前准备

1. 在下载器 U 盘的 `readme.txt` 确认当前型号和固件版本；
2. 从[资料下载](downloads.md)获取与 V2、V3 或 V4 完全对应的升级包；
5. 不要修改升级包文件名后缀或把不同型号的包混用。

!!! danger "型号必须匹配"
    错误型号、来源不明或传输不完整的升级包可能导致下载器无法正常启动。无法确认时先停止，并保留当前 `readme.txt` 中的版本信息。

## MKLink V2

V2 使用 `.rbl` 升级包：

1. 将对应版本的 `.rbl` 文件复制到 MKLink 虚拟 U 盘根目录；
2. 等待复制完成和设备自动处理；
3. 下载器正常情况下会自动重启并删除升级包；
4. 重新打开 `readme.txt`，确认版本和构建日期已经变化。

若设备没有自动重启，先安全弹出并重新上电，再重新复制一次。不要连续快速拔插。

## MKLink V3 / V4

V3、V4 使用 UF2 Bootloader：

1. 拔掉下载器 USB；
2. 按住下载器按键并重新插入 USB；
3. 系统出现名为 `CHERRYUF2` 的磁盘后松开按键；
4. 将对应型号的 `.uf2` 文件复制到该磁盘；
5. 等待复制结束和下载器自动重启；
6. 重新检查 `readme.txt` 或 Web GUI 版本历史。

升级期间 `MICROKEEN` 暂时变成 `CHERRYUF2` 属于正常现象。若没有出现该磁盘，检查按键是否在上电前按下、USB 线是否支持数据以及系统是否完成设备枚举。

## 升级后验收

- 下载器能正常枚举为 CMSIS-DAP 和虚拟串口；
- `MICROKEEN` 磁盘恢复，原有项目文件可读取；
- Web GUI 能发现下载器；
- `readme.txt` 中版本和构建日期符合升级包；
- 用非关键目标板完成一次连接或读取 IDCODE 测试；

固件升级不应删除用户部署的脱机脚本和固件，但升级前仍建议记录文件清单。升级后若脚本 API 有变化，应按新版本说明重新验证生产任务。

## 常见问题

| 现象 | 处理 |
|---|---|
| 复制后没有重启 | 等待磁盘写入完成，重新上电后重试 |
| 仍显示旧版本 | 检查升级包型号、文件是否复制完整、是否进入正确升级磁盘 |
| `CHERRYUF2` 不出现 | 按住按键再上电，换数据线或 USB 端口 |
| 升级后 GUI 找不到设备 | 关闭旧后台，重新插拔并检查设备管理器 |
| 脱机脚本异常 | 对照新固件版本说明和 Python API，重新做触发测试 |

## 使用 AI 协助

> 核对 MKLink 型号、当前版本和升级包，先不要执行升级。

升级是下载器自身的高风险写入。AI 可以核对文件和版本，但开始复制前应再次由用户确认。
