# 在线编译与烧录

## 选择正确的烧录路径

MKLink AI Probe 将“构建工程”和“写入芯片”分开处理。推荐顺序是：

1. 工程已有 Keil 或 IAR 时，使用该 IDE 的原生命令行编译和下载；
2. IDE 不可用或只有预编译镜像时，使用 Web GUI“在线烧录”或 pyOCD；
3. 量产、售后或明确要求离线部署时，使用“脱机烧录”。

某条路径已经开始但失败时，应先查明原因，不要静默换另一种方式继续写芯片。

## 使用 IDE 编译和下载

确认当前 Target、器件、Flash Algorithm 和输出目录。编译应达到零错误，再执行 IDE 下载，并通过 RTT 日志、版本变量或目标板行为验证新固件确实运行。

## 使用“在线烧录”页面

适合已有 BIN/HEX 文件的场景：

1. 打开“在线烧录”；
2. 选择 MKLink 探针；
3. 搜索并选择精确器件型号；
4. 若目标 Pack 未安装，先安装或导入对应 Pack；
5. 选择 BIN 或 HEX；
6. BIN 必须填写正确的下载基地址，HEX 使用文件内地址；
7. 检查镜像地址范围和将要擦除的扇区；
8. 启动作业并等待连接、擦除、编程、校验和断开全部完成。

### STM32F103RET6 实例

本例目标为 `STM32F103RET6`。Keil DFP 使用 `STM32F103RE` 条目，Flash Algorithm 为 `STM32F10x_512.FLM`，器件 Flash 为 512 KiB，基址为 `0x08000000`。HEX 文件使用文件内地址；本次构建的实际数据范围约为 `0x08005000–0x080218F8`，不能把“器件基址”误认为“镜像起始地址”。

Web GUI 作业必须完整经过以下六个阶段：

```text
connect -> erase -> program -> verify -> reset -> disconnect
```

`program` 前应选择镜像覆盖的完整扇区；擦除范围必须与页面显示的镜像覆盖扇区一致。仅上传文件、仅完成 `program` 或命令返回 0 都不能作为验收依据。

![在线烧录及固件预览](../../images/microlink/gui/online-flash.png)

!!! danger "擦除和地址风险"
    全片擦除会永久删除目标 Flash 内容。BIN 基地址错误可能覆盖 BootLoader、参数区或其他镜像。开始前必须核对内存布局。

## 成功判据

- 作业状态为完成，而不是停止中或仅上传完成；
- 校验步骤成功；
- 目标复位后运行新固件；
- RTT、版本号或可观测变量与本次构建一致。

本例完整作业实测状态为 `succeeded`，包含校验和复位，耗时约 10 秒。

设备被 RTT、SuperWatch 或 SystemView 占用时，先停止对应会话并释放资源，再启动在线烧录。

## 使用 AI

> 构建当前 Target 并在线烧录；完成 verify 和复位后，用 RTT 证明新固件运行。
